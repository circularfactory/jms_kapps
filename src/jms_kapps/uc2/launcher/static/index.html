Processes

One process for each module, the Warehouse Management System, and the monitor; a process is live while its service carries a fresh heartbeat in the knowledge graph. Click a name for its recent output, and Clear stops every process and empties the dataset, after it asks.

The two faults

Each module has two fault switches. With skip-reserve it hands a box on without asking first, and the triple store refuses that when the next module holds a box. With complete-without-releasing, as a box's destination, it completes the transport before it gives the box back, which the triple store always refuses. The monitor shows each refusal, and the box still arrives. A module starts with both off.

Boxes on the station

Every box whose possessor is not the Warehouse Management System, with the module that possesses it, and its transport and that transport's status. The Launcher reads them every second with the SPARQL query below.

The query elsewhere

Run the query on the same dataset, in the triple store's workbench or in any other SPARQL endpoint, and you get the same list. The monitor's table of boxes shows these boxes too, beside those the Warehouse Management System possesses.

Topology

      
The grid draws the topology chosen in the picker, and Launch
        launches what the grid shows: it clears the dataset, seeds that topology, and restarts
        every process. Edit makes the grid editable.

      

        Build your own topology
        
Edit opens the chosen topology for editing,
          Empty grid an empty one, and Upload a topology file.
          Click an empty cell to add a module, a module to select it, and the gap between two
          neighbouring modules to cycle their connection: none, one way, the other way, both ways.
          The load check runs on every change, and only a topology that passes it can be
          launched. Download saves a topology file, and jms-uc2 --topology
          <path> starts on one; a file keeps no cells, so it opens where the server
          puts its modules. While you edit, the picker, Empty grid and
          Upload replace the edit, and they and Close ask first
          when it has changed. While a topology that is not shipped runs, the picker has an entry
          for it, and Edit continues from it.

      

      

        The shipped topologies
        
        
The samples pair, tee, grid, line and merge-fault-demo run one way, from
          their entry modules to their exit modules. line is four modules one after another.
          merge-fault-demo merges two streams: skip-reserve on
          Module5 collides with the box that waits on Module6. A topology is refused, before
          anything is cleared, where it has no module or a pure two-way corridor: a module whose
          only two connections both run both ways, where two boxes that meet head-on could wait
          for each other forever. Any other topology loads.

      

      

        The run settings
        
Each setting counts for the next launch. transit time (s)
          is how long a module takes to convey a box, unless the topology gives the module its
          own. deadlock alarm (s) is how long a box that a module holds may wait
          for a Reserve before the module raises the deadlock alarm for it: a warning in the
          module's output that starts with "possible deadlock:" and a notice on the monitor.
          Module strategy and WMS strategy choose how each
          module chooses the neighbours it asks for a box, and how the Warehouse Management System
          picks where a box starts and ends; a strategy whose name ends in "(synthetic)" makes
          traffic that a benchmark can repeat. With collect history checked, the
          launch turns on the triple store's history collection, so that the possessor a box had
          at an earlier time can be read. The monitor starts in "graph only": it reads the
          knowledge graph and nothing else. With Collect the SHACL refusals in one
          monitor checked, it starts in "graph + streams", which also follows each
          service's handover event stream, for the refusals and the deadlock notice: the refusals
          do not travel through the knowledge graph.
